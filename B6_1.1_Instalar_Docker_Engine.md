## 📚 Fundamento

> [!info] Qué estás instalando exactamente
> **Docker Engine** es el programa que gestiona imágenes y contenedores. Se instala como un **servicio del sistema** (un demonio), igual que Samba o Nginx: arranca con la máquina y se queda escuchando órdenes.
>
> Eso significa que Docker **no es una máquina virtual que arrancas**. Es un servicio más de tu Ubuntu. Coherente con lo que viste en B6.0.1: los contenedores son procesos de tu servidor, y este es el programa que los organiza.

> [!warning] El fallo nº1: instalar Docker por la vía rápida
> Vas a encontrar en internet dos atajos. **Los dos dan problemas:**
>
> | Atajo | Qué pasa |
> |---|---|
> | `sudo apt install docker.io` | Instala la versión empaquetada por Ubuntu, que suele ir **muy por detrás**. Te faltarán opciones y `docker compose` (fase B6.7) puede no estar. |
> | `sudo snap install docker` | El confinamiento de snap **restringe el acceso al sistema de archivos**. Los montajes de la fase B6.4 —el corazón del bloque— fallan de formas rarísimas y difíciles de diagnosticar. |
>
> **En esta práctica usamos el repositorio oficial de Docker.** Es tres minutos más de trabajo y te ahorra el bloque entero. Y de paso practicas añadir un repositorio de terceros con su clave GPG, que es una tarea de administración de sistemas de pleno derecho.

> [!warning] Si estás en el aula: `toomanyrequests`
> Docker Hub **limita cuántas imágenes se pueden descargar sin identificarse**, y ese límite lo cuenta por **dirección IP pública**. En clase, los veinte equipos salís a internet por la misma IP del instituto: si todos descargáis a la vez, en algún momento aparecerá
>
> ```
> toomanyrequests: You have reached your pull rate limit
> ```
>
> **No es un fallo de tu servidor ni de tu instalación**, y no se arregla repitiendo el comando. Dos salidas:
> - **Identificarte con una cuenta gratuita** de Docker Hub — el límite pasa a contarse por cuenta y no por IP:
>   ```bash
>   docker login
>   ```
> - **Esperar** a que pase la ventana de tiempo, o hacer la descarga desde otra red.
>
> Si trabajas en casa, esto no te va a pasar. Es un problema de red compartida, y saber identificarlo es exactamente el tipo de diagnóstico que se te va a pedir en una empresa.

> [!example] Vocabulario de esta práctica
> - **Docker Engine:** el motor. El servicio que gestiona imágenes y contenedores.
> - **Demonio (*daemon*):** proceso que corre en segundo plano. Aquí, `dockerd`.
> - **Repositorio de terceros:** fuente de paquetes ajena a Ubuntu, que se añade a `/etc/apt/sources.list.d/`.
> - **Clave GPG:** firma que garantiza que los paquetes vienen de quien dicen. Sin ella, `apt` se niega a instalar.
> - **Grupo `docker`:** grupo del sistema cuyos miembros pueden hablar con el motor sin `sudo`.

## 🛠️ Procedimiento

> [!example] Paso 0 — Prepárate y empieza a grabar
> Léete el ejercicio entero, arranca OBS y preséntate. Ten tu **Ubuntu Server encendido** y acceso con un usuario con `sudo`. Comprueba que tienes salida a internet: `ping -c 3 download.docker.com`.

> [!example] Paso 1 — Actualiza el sistema y prepara los prerrequisitos
> ```bash
> sudo apt update
> sudo apt install -y ca-certificates curl
> ```
> `ca-certificates` permite validar el certificado del servidor de Docker; `curl` descarga la clave.

> [!example] Paso 2 — Añade la clave GPG oficial de Docker
> ```bash
> sudo install -m 0755 -d /etc/apt/keyrings
> sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
> sudo chmod a+r /etc/apt/keyrings/docker.asc
> ```
> Estás diciéndole a tu sistema: *"los paquetes firmados con esta clave son de fiar"*. Sin este paso, el siguiente `apt update` fallará por firma no verificada — **y eso es correcto**, es el sistema protegiéndote.

> [!example] Paso 3 — Añade el repositorio de Docker
> ```bash
> echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
> sudo apt update
> ```
> Fíjate en los dos trozos entre `$( )`: detectan **solos** tu arquitectura (`amd64`, `arm64`) y el nombre en clave de tu Ubuntu (`noble`, `jammy`…). Por eso el comando vale para cualquier equipo sin tocar nada.
>
> Comprueba que la línea quedó bien: `cat /etc/apt/sources.list.d/docker.list`

> [!example] Paso 4 — Instala Docker Engine
> ```bash
> sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
> ```
> Los cinco paquetes: el motor (`docker-ce`), el cliente de línea de comandos (`docker-ce-cli`), el runtime de bajo nivel (`containerd.io`) y dos plugins. **`docker-compose-plugin` lo necesitarás en la fase B6.7** — instálalo ahora aunque todavía no lo uses.

> [!example] Paso 5 — Comprueba que el servicio está en marcha
> ```bash
> sudo systemctl status docker
> docker --version
> ```
> Debe aparecer `active (running)`. Sal del `status` con `q`.
>
> Esto es exactamente lo mismo que hiciste con Samba en su día: **Docker es un servicio del sistema**, ni más ni menos.

> [!example] Paso 6 — La primera prueba de verdad
> ```bash
> sudo docker run hello-world
> ```
> Si ves un mensaje que empieza por `Hello from Docker!`, **el motor funciona**. No cierres el terminal: en la práctica B6.1.2 vas a diseccionar línea por línea lo que acaba de pasar aquí.

> [!example] Paso 7 — Usa Docker sin `sudo`
> ```bash
> sudo usermod -aG docker $USER
> newgrp docker
> docker run hello-world
> ```
> Ahora funciona **sin `sudo`**. Lee la advertencia de abajo antes de seguir: esto no es un truco de comodidad inocente.
>
> Si `newgrp` te da problemas, cierra la sesión SSH y vuelve a entrar.

> [!danger] Lo que acabas de hacer en el Paso 7 (esto entra en el examen)
> Meter tu usuario en el grupo `docker` **equivale a darle permisos de root**. No es una exageración: quien puede hablar con el motor puede arrancar un contenedor que monte el disco entero del anfitrión y modificar cualquier fichero del sistema.
>
> Por eso en un servidor de producción esto se piensa dos veces y solo se hace con usuarios administradores. En tu laboratorio es cómodo y aceptable; en la empresa de tu FCT, pregunta antes.
>
> Volveremos a ello en **B6.4.4**, cuando aprendas a ejecutar contenedores sin privilegios.

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Instalar con `apt install docker.io` o snap | Versión vieja o montajes rotos en la fase B6.4 | Usa **siempre** el repositorio oficial de esta práctica. |
> | Saltarse la clave GPG (Paso 2) | `apt update` falla: *"firma no verificada"* | No te saltes pasos; el orden importa. |
> | `permission denied ... docker.sock` | El usuario no está en el grupo `docker` | Repite el Paso 7 y **vuelve a iniciar sesión**. |
> | `Cannot connect to the Docker daemon` | El servicio no está arrancado | `sudo systemctl start docker` y `sudo systemctl enable docker`. |
> | Olvidar `docker-compose-plugin` | La fase B6.7 no funcionará | Reinstálalo: `sudo apt install -y docker-compose-plugin`. |
> | `toomanyrequests` al descargar | Límite de Docker Hub por IP: toda el aula sale por la misma | `docker login` con cuenta gratuita, o esperar. **No es tu instalación.** |

> [!success] ✅ Verificación: ¿está bien hecho?
> - `docker --version` devuelve una versión **reciente** (24.x o superior).
> - `sudo systemctl status docker` muestra `active (running)`.
> - `docker run hello-world` funciona **sin `sudo`**.
> - `docker compose version` responde (plugin instalado).
> - Sabes explicar **por qué no se instala con `apt install docker.io`**.

> [!question] Comprueba que lo has entendido
> 1. ¿Por qué se añade un repositorio de terceros en lugar de usar el paquete de Ubuntu? Da dos razones distintas.
> 2. ¿Qué función cumple la clave GPG y qué pasaría si te la saltas?
> 3. Docker se ha instalado como un servicio del sistema. ¿Qué otro servicio del curso se comporta igual? ¿Qué comando usas para comprobar el estado de ambos?
> 4. Explica con tus palabras por qué meter un usuario en el grupo `docker` es, en la práctica, darle root.
> 5. Un compañero dice: *"he instalado Docker con snap y me va, así que da igual"*. ¿Qué le contestas y en qué práctica futura se dará cuenta del problema?
